# Design review, October 2026 — finding register and the H-gates

**Status: the review's verdict stands. This is a design plus an M0 skeleton, not an
operational checker. Contracts are NOT ready to freeze until H7 lands; M1 does NOT start
until M0.5 has run.**

An external adversarial review (another model) was run against branch
`claude/m0.6-review-remediation`. That branch reconciles the design documents at
`46440dc`, the M0 skeleton (`5f2db11`), the M0.5 prior-art pass (`1a7440a`), and the
probe mods (`ad39db9`). It returned twelve findings, a Stellaris compatibility section,
and a seven-step corrective order. Five agents took the findings by area, and **every
finding was treated as a claim and checked against the files on this branch before it was
acted on.** None was rejected. Four came out worse than the review stated: the finding
sort key compared raw interned ids minted in parallel stages; warm scans forgot that a
file was malformed; an oversize file that went unparsed made `core.symbol_deleted` fire
for every vanilla definition it shadowed; and Irony's own source contradicts "vanilla is
always lowest" for differently named files.

The August register's verdict on the architecture's *shape* survives here too. Two-layer
overlay → symbol, `MergeMode` as the semantic pivot, and the detect/value/present split all
stand. What failed this time is narrower and worse: **the resolver modelled one
granularity per directory where the game uses two**; **the finding contract had no way to
say "I did not see everything"**; and **the plan's exit criteria could each be passed by
doing nothing**. All three are now contract or plan text. None of them is code yet.

### What M1 now is

M1 is read-only playset inventory; verified enabled order (the launcher order source and
its snapshot protocol move up from M3); same-path conflicts only (Stages A and B,
`Mechanism::SamePath` or `ReplacePath`); bounded evidence with no file bodies;
completeness and certainty printed even with zero findings; and safe static output
(table, JSON, Markdown). It has **no severity and no ranking**: policy arrives at M5.
`DirectoryScan` alone never yields a winner. Archive mods are inventoried with content
unread. `replace_path` shadowing of earlier mods is reported as undetermined until M0.5
answers its scope. M1 ships only through the release gate (H33), on CI-built
artefacts and three real playsets. `15` § "M1" has the exit.

# Open disagreements and judgement calls

None of the five owners disputed another's disposition, and no finding was rejected.
These are the choices someone may reasonably reverse, plus the verifier's non-blocking
issues (B2–B8) and where each one went:

1. **The 14 FIOS directories ship as `order = "fios"`, not `unknown`** (resolver). The
   only source is prior art, and Irony's at that. Marking them `unknown` would make every
   differently named conflict in them unresolvable, which leaves no model at all. The
   chosen trade is to state them and cap their `semantics` certainty at `Assumed`. Revisit
   when probe P3 (V02) runs.
2. **M1 ships no severity** (delivery). `docs/README.md` describes the tool as ranking
   outcomes "by how likely they are to matter"; the first release does not. The argument
   is that a score printed before calibration is a guess in bold. The cost is that a large
   playset's M1 report is long and flat. **Decided (owner, 2026-10-17): M1 ships no
   severity.** Both READMEs now say ranking arrives at M5.
3. **Finding 12(b) was more open than this register first said** (B2, corrected).
   An earlier draft called 12(b) narrow because `13` had known-bad and MRR guards. That
   was wrong. Those guards measure recall only over fixtures the author wrote. The first
   H31 draft then sampled its "recall" labels from the tool's own output, where a missed
   conflict cannot appear. `13` and the M5 exit now take recall from a census built
   independently of the tool's output: seeded conflicts, plus a reference enumerator that
   shares no code with `smd-parse`, `smd-index`, or `smd-rules`. A real conflict that goes
   unreported counts as a miss. What remains open is the enumerator's own coverage. It
