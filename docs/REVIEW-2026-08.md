# Design review, August 2026 — finding register and M0 gate

**Status of the design: NOT ready to freeze contracts; NOT ready to begin M0.**

Five reviews were commissioned against the design at commit `f788a45`. Four completed.
One did not run (see § Unreviewed). This document records every finding that changes a
decision, its disposition, and the list of things that must be settled before the first
line of code.

The architecture's *shape* survived review. All four reviewers independently reached
the same structural conclusion: the two-layer decomposition (overlay → symbol, joined by
`live`), the detect/value/present split, `MergeMode` as the noise-reduction lever, and
CLI-before-GUI are correct and should not be relitigated. **Every blocking defect is in a
join, a sort key, an enum's coverage, or a claim never traced against the library it
names.** None require redesign. All are cheaper to fix now than at any later milestone,
which is the entire argument for fixing them before M0.

## Unreviewed: Paradox domain accuracy

R5 terminated on a session limit before producing findings. It was to verify the design's
factual claims about Stellaris against the wiki, Irony Mod Manager, CWTools, and the
`tiger` validators.

**This is the highest-risk unreviewed area in the project.** It covers load-order
direction, `replace_path` semantics, and the per-directory merge-mode question — and
three of the four completed reviews independently flagged merge-mode correctness as
load-bearing for the entire severity model. `docs/VERIFY.md` remains the only record of
these assumptions, and it is unverified by construction.

**Disposition:** R5 must be re-run, and its scope is now *also* covered by the M0.5
ground-truth milestone (G18). Neither substitutes for the other: R5 checks the design
against documented prior art; M0.5 checks it against a running game.

# The M0 gate

Nothing below is optional. Each item is either a one-way door, or a change whose cost
rises by an order of magnitude once code depends on it.

## A. Contract-level (lands in `smd-core` / `smd-api`)

These change type definitions. Discovering them after the freeze means either a
`CONTRACT_VERSION` bump invalidating every cache, or living with them permanently.

| # | Change | Why it cannot wait |
| --- | --- | --- |
| **G1** | Split `RawFact` (file-local, cacheable, string-based) from `Fact` (interned, never serialised). Add contract clause: *interned ids are scan-local and must never be serialised, cached, or cross the API boundary.* | The cache as specified attributes facts to the wrong mod. Warm scans — the normal path — are silently wrong. |
| **G2** | `SourceId` becomes identity only (discovery order). Precedence moves to `rank: Vec<u32>`. **Remove `Ord`/`PartialOrd` from `SourceId`** so precedence comparison must route through `rank`. Add `SourceMeta { key, name, rank, enabled, role, order_confidence, deps }`. | Reorder currently invalidates ~500k `live` flags and every `SmallVec` ordering. Hours now; rewrite of `smd-index` and every rule at M9. |
| **G3** | `Resolution.outcome: Outcome { SingleWinner, Coexist, MergedInternally, Deleted, Unknown }`. Debug-assert that a "discarded" finding has `SingleWinner`. | Under `Additive` the tool currently states the exact opposite of the truth, at High severity, in bold. |
| **G4** | Add `MergeMode::MergeByKeyAdditiveBody` and `MergeMode::Unknown`. Profile gains `additive_children`. | `on_game_start` is hooked by nearly every content mod. v1 would ship a ~200-participant High finding that is 100% false, and it would be the loudest thing in the report. |
| **G5** | Widen `Subject` with `LocKey{lang,..}`, `Event{namespace,ordinal}`, `Directory{declarer,prefix}`. Add a total final tiebreaker (full participant vector, then canonical evidence hash). Define `Ord` on `Subject` and `Severity`. | Sort key is non-total *and* fed by `HashMap` iteration. The determinism gate passes most runs and fails randomly — the worst failure mode for a guard. |
| **G6** | `ScanEpoch(u64)` on every request and response; mismatch returns `Err(Stale)`. `Event::ScanInvalidated(ScanEpoch)`. | A query issued before an `Arc` swap can return after it. The virtualiser splices two snapshots into one scroll position. |
| **G7** | Add `Query::OpenResultSet(FindingQuery) -> ResultSetId{len, epoch, facet_counts}` + `Query::Page(ResultSetId, offset, limit)`, LRU-evicted. Add `GroupedQuery{group_by, expanded, offset, limit}`. | Offset pagination cannot express sorting, conditioned facet counts, or grouped trees. Doc 11 states the "engine holds truth" rule and then designs a UI that cannot obey it. |
| **G8** | Replace `Rule::applies_to() -> &[&str]` with `Rule::requires() -> &[FeatureTag]`, tags a closed vocabulary in `smd-core`, declared per profile. | Game ids in `smd-rules` fail the design's own lint gate. Feature tags also make M8's exit criterion mechanical rather than hopeful. |
| **G9** | Add `cancel: &CancellationToken` to `RuleCtx`; require a check per outer-loop iteration. Add `JobState::Cancelling`. | Cancellation cannot reach stage 7 at all. A superseding scan has a real multi-second state the API cannot express. |
| **G10** | Replace `Resolution.identical: bool` with `Agreement { AllIdentical, LosersMatchWinner, Differs }`. | `identical` is computed over all participants including vanilla, so the −50 discount never fires on the vendored-copy case it was built for. |
| **G11** | Add `Rule::evidence() -> &[(&str, EvidenceType)]`. Enumerate derived explanation placeholders as a closed set in `smd-core`. `xtask lint` cross-checks every modifier key and every `{placeholder}` against it. Debug-assert rules emit only declared keys. | The one cross-crate, cross-language contract in the design with zero checking. A typo'd modifier key silently never fires, forever. |
| **G12** | `Rule::run` returns `Vec<Finding>` instead of taking `&mut FindingSink`. | `&mut T` is not `UnwindSafe`; the isolation claim must be enforced by the type, not by an `AssertUnwindSafe` whose precondition is convention. |
| **G13** | Define the types named but never specified: `EvidenceValue`, `SourceTable`/`SourceMeta`, `SymbolKey`, `ResolvedDependency`, `Interner<T>`, `Basis`, `Impact`. Split `Basis` into `mechanism: Mechanism` and `confidence: Confidence` (currently two axes in one field). | A document opening "these are the only types crates share" cannot omit types every crate touches. |
| **G14** | Decide `FactPayload::Reference`'s fate. Either gate `Capabilities::REFERENCES` off for v1 (drop 120 MB from the budget, drop the `referenced_by_others` modifier, defer `core.dangling_reference`), or commit to a type map. | A contract field with no producer. Untyped reference extraction matches `owner`, `root`, `value`, `yes` — impact analysis becomes noise and every score inflates by 20. **Depends on decision D2.** |
| **G15** | `FactPayload` variants are **append-only**; insertion or reordering requires a `CONTRACT_VERSION` bump. Snapshot the discriminant assignment. Widen `Capabilities` to `u32`. | rkyv/postcard encode variants by discriminant. Inserting one silently misdecodes every cached fact. |
| **G16** | Add `MergeMode` to path classification rather than to each `DefSite`; add loc `version_ordinal` to `FactPayload::LocKey`; make `EventId.ordinal` an `EventOrdinal { Num(u32), Name(SymbolId) }`; state that all spans are **raw-file byte offsets**. | Four parser/contract mismatches. `EventOrdinal` matters most: non-numeric event ids are legal and `pdx.event_id_dup` carries the highest base weight. |
| **G17** | Add `core.symbol_deleted` to the v1 catalogue, backed by a `Resolution::Deleted` / `all_dead()` query. Base weight above `symbol_collision`. | The entire v1 catalogue is "≥2 of something". A symbol that existed and now exists nowhere is structurally unreachable — and that is the class of bug users open the tool to find. |

## B. Build, toolchain, and dependency

| # | Change | Why |
| --- | --- | --- |
| **G18** | Pin `[profile.release] panic = "unwind", lto = "thin", codegen-units = 1`. Add a profile-audit lint asserting it. Add a test that a deliberately panicking rule is contained. | Size targets push toward `panic = "abort"`, which makes `catch_unwind` a no-op. Green CI, dead user. |
| **G19** | Replace `jwalk` with `ignore` (`WalkBuilder::build_parallel`). | jwalk's README declares it unmaintained; it is rayon-based, contradicting the doc's own IO-pool rule; its parallelism is per-directory and mod trees are wide and flat. `ignore` also supplies the glob matcher the profile system needs. |
| **G20** | Drop `redb`. Use the already-bundled SQLite for the parse cache (WAL, one table, `DELETE … ORDER BY atime LIMIT n` eviction). Never write LRU metadata on the read path. | The "zero C deps" rationale is cancelled by the adjacent `rusqlite(bundled)` row. redb cannot express the specified LRU without turning 400k warm reads into 400k writes. |
| **G21** | Default to `read()` into a pooled buffer; mmap only above a measured threshold and only under the read-only game install directory. Add a "file modified during scan" row to the failure table. | mmap page faults raise SIGBUS/`EXCEPTION_IN_PAGE_ERROR` — uncatchable. Windows additionally **locks mapped files**, so a Steam workshop update mid-scan fails against the user's own game, violating the read-only promise. And mmap is slower than `read()` at a 3 KB mean file size. |
| **G22** | One `Arc<ThreadPool>` owned by `smd-engine`; `ignore` and every parallel entry point go through `pool.install()`. `xtask lint` bans rayon iterator entry points outside `smd-engine`. | Bare `.par_iter()` in `smd-rules` targets the global pool — neither of the two pools the design describes. A global pool also makes doc 13's varied-thread-count determinism test impossible. |
| **G23** | Strike `specta` as a peer of `ts-rs`. Evaluate `tauri-specta` **only if** decision D1 keeps Tauri. No bare `u64` across the IPC boundary. Make query handlers `async`/`spawn_blocking`. | `specta` 2.x has been RC since 2023. `u64` over JSON loses precision above 2^53. Sync command handlers serialise on the main thread the design says must never exceed 1 ms. |
| **G24** | `edition = "2024"`. State the dual-toolchain reality: stable for build and test, nightly for the fuzz job only. | Doc specifies edition 2021 in 2026 and commits to "stable toolchain" while mandating `cargo-fuzz`. |
| **G25** | Parser must be **iterative with an explicit depth cap** (256), emitting a `Diagnostic` at the cap. | `catch_unwind` cannot catch stack overflow, and doc 13 explicitly fuzzes 10k-deep nesting against a "never panics on any byte sequence" guarantee. |

## C. Budget and measurement

| # | Change | Why |
| --- | --- | --- |
| **G26** | Add a stat-keyed layer in front of the content-addressed cache: `(volume_id, file_id, size, mtime_ns) → content_hash`. | Without it, a warm scan must re-read and re-hash 1.2 GB to compute its own cache keys. The 2 s warm target is unreachable by construction, not merely unmet. |
| **G27** | Replace the invented reference workload with a measured one (file count, byte total, by-extension histogram across three real 200–400 mod playsets). Restate every budget row so the columns sum. | 400k files / 1.2 GB implies a 3.0 KB mean; with art excluded that leaves ~640 bytes per text file, which is wrong by 3–5×. Six other decisions inherit the error. The warm column currently sums to 8.5 s against a stated 2 s. |
| **G28** | Budget engine-heap and total-process-tree RSS as two separate numbers. Correct the symbol interner (~1.3M entries, not 500k — loc keys are symbols). Add the finding vector, the merge transient, and the WebView tree. Consider `mimalloc`. | Peak lands at ~950 MB–1 GB against a 900 MB target the doc claims prevents OOM. Allocator stats cannot see mmap'd pages or the WebView process. |
| **G29** | Split benches: CPU-only microbenches on Linux with a 10% gate; full-pipeline IO benches on **Windows**, trend-reported with a loose or no gate. | Every platform-sensitive decision is budgeted on Windows and benchmarked on Linux. A 10% gate on a shared cloud runner will be red constantly and disabled within a month. |
| **G30** | State what the 100 ms reorder covers, and grey the findings table while they re-derive — or drop the sandbox until G2 lands. | Reorder re-*derives* findings rather than re-scoring them; 100 ms and the 2 s analyse budget describe the same work. |

# Open decisions requiring the owner

These are not review findings. They are forks where reviewers identified a real
alternative and the choice is a product decision, not a technical one.

**D1 — GUI delivery.** Keep Tauri, or ship CLI + a self-contained interactive HTML
report (escalating to `smd-cli serve` for the live-engine features), with Tauri as a
post-v1 upgrade? The second removes WebView2's offline-installer trilemma, WebKitGTK
skew, the NVIDIA blank-window bug that disproportionately affects a gaming audience,
AppImage bloat (real figures are 76–100 MB, not the doc's 40 MB), macOS notarisation and
its $99/yr prerequisite, the generated-type IPC seam, and the Playwright job. It costs
the live reorder sandbox and on-demand diff fetch unless `serve` is built. Blocks G7,
G23, G30, G35, G38.

**D2 — Reference extraction in v1.** Gate `Capabilities::REFERENCES` off (dropping
impact analysis, the `referenced_by_others` modifier, and `core.dangling_reference`), or
commit to a type map? Depends on G45. Blocks G14.

**D3 — Licence and product name.** G43 and G44. Both are one-way doors that gate reading
prior-art source and reserving names.

**D4 — Scope against the corrected schedule.** 8–11 months solo is roughly 4× the
roadmap's implied scope. Narrow v1, accept the timeline, or add people?

# Findings deferred (non-blocking)

Recorded so they are not rediscovered. Safe to address after M0 under the stated
compatibility rules: `body_hash` normalisation specification (comment-stripping must
operate on the token stream, not raw bytes; lossy-decoded files excluded from
identical-detection); two-phase scoring stratification and the aggregate population for
`same_mod_findings_gte`; `meta.patch_candidate` suppression needing a participant
predicate rather than subject equality; score-scale saturation (base weights 65–85
against a 90 critical band leave most of the modifier space inert); `MergeMode::Single`
having no directory-keyed overlay to act on; `localisation/replace/` precedence being a
path relation the overlay cannot express; intra-source ordering (`00_`/`zz_` filename
convention) being unmodelled; `@script_variables` having no fact variant; per-mod and
per-pair aggregate types being absent though the GUI depends on both; calibration
measuring self-consistency rather than ground truth; redb/SQLite commit batching;
Playwright not being Tauri 2's E2E path; diagnostic event batching.

# What survived review

Do not relitigate these. All four reviewers converged on them independently.

- The two-layer decomposition, and `live` as the join between overlay and symbol layers.
- Detection / valuation / presentation as three crates, with policy the only writer of
  `score` and `severity`.
- `MergeMode` as the semantic pivot, sourced from profile data rather than code.
- `body_hash` as the identical-copy discount (mechanism correct; predicate wrong — G10).
- Capability-gated index building.
- `Site` on every finding with a debug assert — verifiability as a type-level invariant.
- Content-addressed parse caching as an *idea* (payload broken — G1).
- `EvidenceBag` structured rather than formatted, with a separate explanation catalogue.
- The language-discipline table in doc 09, rated the most mature thing in the set.
- Read-only stance; never abort a scan; `Diagnostic` as data.
- Determinism as a testability requirement.
- `VERIFY.md` existing at all, and encoding load-bearing assumptions as data.
- M8 as a falsification test of the game abstraction.
- CLI before GUI, for the stated reason.
